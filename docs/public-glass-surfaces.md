# Public Liquid Glass surfaces: geometry, layers, interaction

**Scope:** public `/`, `/projects` and `/login` on dofinances.com. **Out of scope:** `/app`, its authenticated dashboard, and studio. Those assets and renderers are not changed.

## Evidence and limits

Reference: [liquid-plexiglass-oracle](https://github.com/lukehanna12/liquid-plexiglass-oracle), commit `6f59bb46423e2e11e50ef7da4aabae4d3ea35d40`, target macOS 26.5.1 build 25F80, Apple M2/G14G. `model/foundation/model/geometry_331_compact.json` supports the **finite** ten-case relationship `d=min(resolvedBackdropWidth,resolvedBackdropHeight)`, not the first mosaic square's width. `model/primary_evidence/scalars/live_public_geometry_radius_heldout.json` supports 52 held-out public blur-radius observations. `model/primary_evidence/sdf_bridge/status.json` retains finite mode4/mode5 live GPU bindings and the four-lane native comparison.

These do not prove a universal browser/native implementation. `model/OPEN_PROOFS.json` still lists native semantic equivalence, runtime output color/EDR, and one scalar family. CSS-to-private-SDF projection, unrestricted affine/elliptical corners, native texture-mip selection, and native hover/click dynamics remain unproved. Visual appearance does not constitute Oracle evidence.

## Public shared surface model

`assets/home-dashboard/dashboard-glass-model.js` defines geometry, CSS corner-overlap normalization, surface shape classification, content roles, layered backdrop declarations and interaction springs. It accommodates squares, circles, horizontal/vertical capsules, rectangles and four-corner rounded rectangles.

The Oracle's `nativeMode` is still the finite 4/5 corner comparison. For true CSS round-ended silhouettes, `renderMode=6` deliberately uses an *authored analytic capsule/circle field*, not a fictional Apple mode-6 fragment. All shape branches feed the same WebGPU refraction, blur distribution, LOD, tint-film and hover/press lighting stages. The original mosaic mode4/5 code is preserved.

Each public surface now owns its own resolved minimum dimension and projected blur word. The first-square optical-size override is removed. The public SVG fallback also calls the common geometry projector; its SVG blur remains a browser approximation rather than a native Metal equivalence.

Home glass has two actual GPU layers: the moving squares at layer 0, and the bottom CTA capsules at layer 1, which refract the completed layer-0 scene with refreshed mip levels. The layer planner rejects missing or recursive backdrop dependencies. The public Sign in and Projects routes preserve their present scroll, DOM and GPU presentation semantics; other arbitrary HTML backgrounds are not captured.

Content roles distinguish text, icons, flat shapes, mixed overlays and glass silhouettes. Existing Projects title glyphs retain their GPU alpha mask; ordinary foreground labels/icons remain accessible DOM content on the glass.

The public square and pane controllers use the same reversible spring equation and shape-aware hit regions. An oblong capsule has a longer browser hover footprint; the original square's material response and press strength are preserved. No Apple-exact event law is claimed. Reduced motion and reduced transparency behavior are retained.

## November 22, 2026: homepage capsule backdrop-coordinate isolation

The same shared WebGPU shader renders square mosaic tiles, the homepage's three hover-revealed capsules, and the route-owned Sign in/Projects glass. An earlier mistake used `authPane = tile.properties.y < 0` to select **both** the common glass material and the separate route-scrolling backdrop coordinate calculation. Home CTAs have material tag `-9`, so they incorrectly took the scrolling branch. Their home uniform has `fit.w = 0` by design, and the shader's `max(1, fit.w)` therefore treated the backdrop as **1 physical pixel high**, causing near-total vertical clamp-to-edge sampling and concealing the moving squares behind the capsules.

The coordinate branch now requires `routePane = authPane && !homeCapsule`. Homepage capsules use `backdropPosition = in.position.xy` and `backdropExtent = state.viewport.xy`, exactly like squares, and sample the same frame's `compositeSceneView` with current moving squares. Only /login and /projects route panes use their own positive scroll-scene height and canvas offset. This fixes a deterministic host/shader wiring error; the 25F80 native Clear parameter observations and their still-unproved final output semantics are unchanged. A regression test prohibits reintroducing the `if(authPane)` backdrop-geometry branch.

## Regular material (shared public renderer)

The same WebGPU pipeline now accepts `data-glass-material="regular"` on any existing registered public glass element, or a containing element as an inherited default. Explicit `clear` overrides inheritance. The default remains Clear and preserves all existing role-specific optical profiles. A runtime caller can also use `window.__dashboardGpuControls.setMaterial(element,"regular")`. No page is switched to Regular by default.

`dashboard-glass-material.js` owns the independent material contract and finite native inputs. An additional eight-float per-instance storage buffer carries the material flag, inner refraction in device pixels, mip-origin projection and face parameters; the existing 20-float geometry/interaction ABI and numeric route tags remain unchanged. Both the full and route-only GPU passes bind the same material storage and shader. The material choice does not select a shape, hit region, route, backdrop coordinate space, tint, animation or z-order.

Target evidence: Oracle 44c7fe3, `E-P-SWIFTUI-REGULAR-FACE-GEOMETRY-FINITE`, `E-P-SWIFTUI-TINT-SCHEME-NATIVE-FINITE`, 52 held-out public blur-radius cases and twenty-case native scale/encoder joins. Regular geometry: inner amount max(-60,-.8d), height min(20,.25d), zero outer; blur radius clamp(2+((d-48)/112)*2,2,4), observed .25 layer scale and finite .4f word multiplier. All five public blur opacities are one, and refraction mixing opacity is zero. The full-resolution browser pyramid uses a two-level mip origin projection for the quarter-resolution native input; exact native sampling/scale and Q remain open. Face endpoints and fill are stable in the sampled 65–220pt controls; smaller controls have nonrepeating adaptive inputs, so the explicit 58.5pt representative is a bounded browser profile, not a native adaptive law. The native fill is projected using a linear browser blend; its exact matrix execution is not proven. Existing browser interaction and tint assumptions remain shared.

No screenshots or displayed-image comparisons are used. Regular is a full WebGPU material, not a CSS simulation; existing non-WebGPU fallback and the opt-in legacy compositor diagnostic are not native Regular renderers. /app and Studio remain unchanged.

### Superseded: Projects native-scroll geometry synchronization

The prior viewport-fixed canvas could not guarantee alignment with independently compositor-scrolled DOM artwork, title and action: a scroll reversal could move the DOM before WebGPU finished a new frame. Projects now places its existing canvas in the same native scroll content coordinate space (Login retains its viewport-fixed default). Submitted card-local geometry and the band boundary remain invariant while the browser scrolls that common subtree, including between GPU submissions. The raw half-resolution capture covers the full content attachment and uses a source-only wallpaper reprojection based on the actual canvas bounds, followed by original artwork and the same mip generation. It is resized on extent changes, not scrolling. The shader converts its existing displaced wallpaper UV to content UV for the inactive Clear band; all optical constants, color, boundary layout and original high-resolution DOM artwork are retained. Scroll-triggered project GPU work is coalesced into one RAF instead of a synchronous duplicate submission plus RAF; the stationary pointer is reprojected without adding artificial velocity. Fixed wallpaper refraction still updates asynchronously as new GPU frames arrive; exact compositor-time wallpaper pixels are not guaranteed. Geometry alignment does not rely on that update.

### No synthetic artwork-partition highlight

### Authored foreground source composition

The original GPU layer stack included wallpaper, artwork and glass faces but excluded ordinary foreground text, badges and glyphs. HTML was painted above the final glass canvas, bypassing refraction. The shared dashboard-glass-source-paint.js module supports explicitly registered source nodes (data-glass-paint="scene" or "foreground"). DOM is the layout and accessibility authority; authored glyphs, flat fills, vector paths and decoded images are rasterized as transparent source textures, cached in local paint coordinates, and composed with premultiplied source-over on WebGPU. No screen/DOM capture, CSS optical filter, or change to existing glass coefficients. Duplicate DOM paint is suppressed only for valid GPU-owned sources. Copyright enters the original backdrop mip pyramid, Home icons enter the moving-square composite, and Projects card contents enter the attachment immediately after their owner glass. Higher glass uses a complete preceding attachment and regenerated mip levels, never feedback. Expansion close uses layer 1, dropdown layer 2; the second intermediate attachment is allocated only when both are active. The explicitly authored-source contract does not capture arbitrary unregistered HTML or browser-native editable widgets. Legacy/no-GPU presentation retains DOM foreground. This is a browser compositing correction, not a new claim of exact Apple font or compositor output.
